# Break-Glass 应急账号运维手册

Break-Glass（应急账号）是系统最高权限后门账号，凭据**只存在操作系统环境变量**，与业务数据库完全隔离。数据库被清空、回滚、损坏都不影响该账号登录，用于灾难修复。

## 1. 凭据管理

### 1.1 生成

```bash
cd backend
python scripts/generate_super_admin.py            # 随机用户名
python scripts/generate_super_admin.py --username bg_ops_admin
```

脚本输出 4 行 env 片段（`SUPER_ADMIN_USERNAME / PASSWORD / PASSWORD_HASH / ENABLED`），**明文密码只打印一次**，立即存入团队密码管理器。脚本不写文件、不碰数据库。

### 1.2 部署与更换

1. 将 env 片段写入服务器环境变量（或 `backend/.env`）；
2. 重启后端服务生效；
3. 更换密码 = 重新生成哈希 → 更新 env → 重启。初始化向导第 1 步提供 Web 端哈希生成工具（只生成哈希，不改环境变量）。

### 1.3 环境变量说明

| 变量 | 说明 |
|---|---|
| `SUPER_ADMIN_USERNAME` | 登录用户名，精确匹配 |
| `SUPER_ADMIN_PASSWORD_HASH` | bcrypt 哈希（`$2a$/$2b$/$2y$` 60 字符），禁止明文 |
| `SUPER_ADMIN_ENABLED` | `true` / `false`；`false` 时禁止登录，但**登录尝试仍计入防爆破阶梯** |

### 1.4 备份策略（重要）

**仅备份数据库是不够的。** 必须把三项 `SUPER_ADMIN_*` 环境变量纳入独立的机密备份（密码管理器 / 密钥保险库 / 离线密封信封）。数据库备份恢复后，环境变量凭据依然有效——这正是 Break-Glass 的设计目的。

## 2. 存储与安全边界

- 不写入任何业务表（users / sys_config / 会话表均无该账号）；会话只存 KV（Redis）中的布尔标记 `is_break_glass: true`，无 user_id；
- 闲置超时与普通管理员一致（后台「会话空闲超时」全局配置），支持手动登出，**不存在永久会话**；
- 权限：放行全部后台能力、豁免 RBAC 与 IP 黑名单；**不豁免 IP 白名单（内网限制）**——外网直接拒绝登录；
- 后台用户列表、管理员列表永不显示该账号；特权：可清空数据库内全部 admin 账号（不受「至少保留一个 admin」保护限制），用于灾难修复；
- 所有操作审计日志的操作者固定为 `[BREAK_GLASS_ESCAPE]`，可查询、可导出，无无痕后门。

## 3. 防暴力破解（每 账号×维度 独立阶梯）

维度：来源 IP、浏览器指纹（前端 canvas+字体+屏幕+UA 生成，仅提高攻击成本，服务端不信任）。存储在 KV（Redis）中，与业务库无关。

阶梯：初始 3 次密码尝试 → 封禁 5 分钟；此后每次解禁仅 1 次机会，再错依次封禁 10 分钟 → 30 分钟 → 1 小时 → 2 小时 → 5 小时 → 24 小时 → **永久封禁该（账号×维度）组合**。

- 对外一律提示「用户名或密码错误」，真实原因仅写入审计日志；
- 封禁只拦截 Break-Glass 登录，公开页面与其他账号登录不受任何影响；
- `SUPER_ADMIN_ENABLED=false` 时登录尝试仍计入阶梯；
- 后台「安全 → 封禁管理」可解封（含永久）与重置计数。

## 4. ⚠️ 高危操作警告

**严禁同时执行以下两项操作：**

1. 设置 `SUPER_ADMIN_ENABLED=false`（关闭应急账号）；
2. 删除数据库中全部业务管理员账号。

这会导致整个后台锁死，无任何登录入口，只能登服务器改环境变量重启恢复。

**建议**：日常保持 `SUPER_ADMIN_ENABLED=false`，仅在灾难修复时临时开启；修复完毕立即切回 `false`，不要长期开启应急账号。

## 5. 反向代理 / CDN

防爆破的 IP 维度依赖真实客户端 IP：务必在反代/CDN 配置 `X-Forwarded-For` 透传，并把代理地址加入 `TRUSTED_PROXIES`，否则所有请求都会被视为同一代理 IP，IP 防护失效。

## 6. CG-NAT 与永久封禁复核

移动网络/企业出口常共享公网 IP（CG-NAT），自动永久封禁存在误伤可能。建议：

- 定期（每周）在「安全 → 封禁管理」复核永久封禁列表；
- 发现误伤立即解封（支持解除永久封禁）；
- 高误伤环境下可与开发评估调整阶梯策略（如关闭自动永久，永久封禁仅由管理员后台手动录入）。

## 7. 灾难恢复速查

| 场景 | 处置 |
|---|---|
| 全部管理员密码丢失 / 账号被停用 | 开启 `SUPER_ADMIN_ENABLED=true` → 重启 → Break-Glass 登录后台 → 恢复/重建管理员 → 切回 false |
| 数据库回滚/恢复后 | Break-Glass 凭据在环境变量中，不受影响，直接登录修复 |
| Break-Glass 密码遗忘 | 无法找回（哈希单向）。用生成脚本重新生成 → 更新 env → 重启 |
| 应急账号被暴力破解封禁 | 后台管理员在「封禁管理」解封；或清理 Redis 中 `bf:ban:break_glass:*` 键 |
| 系统处于未初始化状态（system_initialized=false） | 仅 Break-Glass 可登录，登录后自动进入初始化向导 |
