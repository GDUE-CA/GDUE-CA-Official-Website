## 项目整体定位

- **项目名称**：可复用SaaS通用底层架构
- **上层业务实例**：高校计算机社团官网

**核心铁律**：

1. 底层 100% 通用、无社团硬编码、无业务写死
2. 可无缝迁移企业 SaaS / OTA / 内部 OA 系统
3. 严格分层：立即落地 / 中期基建 / 远期企业规划
4. 不做过度架构、量力而行、稳健工程化

## 一、立即落地｜强制全项目遵守｜零成本改习惯

### 1. 全站文案 100% i18n 外部化

- 所有页面文字、按钮、提示、弹窗、Toast、报错禁止硬编码
- 所有展示文本使用 i18n Key
- 文案与代码完全解耦：改文案不改动前后端代码、无需部署

### 2. 彻底消灭魔术数字 / 魔术字符串

- 后端所有状态、类型、权限统一 Python Enum
- 前端所有状态、类型、权限统一 TS enum / as const
- 所有阈值（大小、时长、次数、限制）全部放入：环境变量 / 配置文件 / 数据库配置表
- 禁止写死在业务代码行内

### 3. 配置与业务逻辑分离（简易 Feature Flag）

所有模块开关可后台动态控制：

- 注册开关、投稿开关、评论开关、活动开关
- 不用改代码、不用部署、随时启停业务

### 4. OpenAPI 严格契约驱动开发

- 后端 Pydantic = 唯一真实数据源
- 前端全部 TS 接口类型自动从 OpenAPI 生成
- 后端模型变更 → 前端直接编译报错
- 杜绝口头约定、字段不一致、隐藏 BUG

### 5. 全站统一响应体（强制 100%）

所有接口禁止裸返回，统一结构：

```json
{
  "code": 0,
  "data": {},
  "message": "",
  "request_id": ""
}
```

- 业务逻辑只判断 `code`
- `message` 仅展示、绝对不参与逻辑判断
- 所有错误未来支持 i18n 翻译映射

### 6. 全局统一异常体系

- 后端：全局异常中间件、统一错误码、隐藏生产堆栈
- 前端：全局拦截所有网络/业务错误、统一 Toast
- 页面禁止手写 alert、独立错误判断

### 7. 双日志体系（系统日志 + 不可篡改审计日志）

**系统日志**：debug / info / warn / error + Request-ID 全链路追踪

**审计日志（企业级合规）**：

- 仅追加、不可修改、不可删除
- 所有写库操作必须记录：
  - 操作人 ID
  - UTC 操作时间
  - 客户端 IP、IP 属地
  - User-Agent
  - 客户端时区
  - `old_value` 变更前快照
  - `new_value` 变更后快照

### 8. Secure-by-Default 安全默认拒绝

- 权限默认全部拒绝，必须显式授权
- CORS 白名单、禁止 `*`
- Cookie / Token：HttpOnly + SameSite
- 前端 Zod + 后端 Pydantic 双层强校验
- 信条：所有前端数据全部不可信

### 9. 后端权威系统计时器（防篡改、跨时区通用）

**后端规则**：以标准 HTTP `Date` 响应头作为服务器基准时间（由 uvicorn / 反向代理自动添加，不再使用自定义头）：

```
Date: Sat, 11 Oct 2026 00:00:00 GMT
```

- `/api/*` 响应一律 `Cache-Control: no-store`，保证 `Date` 恒为实时（缓存命中的响应 `Date` 是过期时间）
- `Date` 不在 CORS 默认可读白名单内，跨域部署时必须出现在 `expose_headers` 中

**前端 `useSystemTimer` Hook**：

- 维护服务端时间偏移量
- 前端时钟 = 服务器基准时间 + 流逝时间
- 永远不使用本地 `new Date()` 做业务时间
- 同步时机：每次 API 响应（不额外轮询校准接口）
- `Date` 精度为秒：取秒区间中点（+500ms），偏移变化不足 1 秒时不更新，避免倒计时抖动
- 提供工具：`countDown` / `countUp`

**业务铁律**：所有限时逻辑、过期判断、截止校验全部后端执行；前端时间只做 UI 展示，不参与任何业务判定

### 10. 全球标准时区体系（完全对标手机相册 UTC 机制）

**数据库唯一规则**：所有时间字段强制 ISO-8601 UTC Z 结尾；禁止本地时间、禁止北京时间、禁止时区偏移存储

**后端规则**：后端完全不做时区转换，只做时间大小对比

**前端展示规则**：

- 普通内容（博客、评论、通知、动态）自动跟随访问者浏览器时区：英国人看英国时间、中国人看北京时间，同源不同展示

**用户填表时间规则**：

- 前端将用户「本地选择时间」自动转成 UTC-Z 传给后端
- 数据库永久存 UTC
- 展示再自动适配访问者时区

**特殊业务固定时区（线下活动）**：可选字段 `fixed_timezone`
- 有值 → 强制固定时区展示
- 无值 → 跟随访客时区

**远期规划**：用户个人时区偏好设置 `preferred_timezone`；优先级：用户设置 > 浏览器时区

## 二、中期迭代｜业务稳定后落地｜项目基建

### 11. RBAC 细粒度权限系统

- 不使用简单管理员/用户二元区分
- 最小权限单元：权限点字符串（`article:create`、`article:edit`、`notice:manage`、`user:manage`）
- 角色 = 权限集合
- 代码只校验权限点，不判断角色
- 新增角色无需改代码，后台勾选即可

### 12. 100% 数据库版本化迁移

- 禁止手动改表、禁止手动 SQL
- 所有结构变更走 Alembic 迁移脚本
- 四环境：本地/测试/预发/生产结构完全一致

### 13. 多环境完全隔离

- dev / staging / prod 三套独立数据库、独立配置
- 代码无任何环境硬编码判断

### 14. Github Actions CI 强制门禁

main 分支必须通过：Lint / 格式化、TS 全量类型检查、Python 类型检查 mypy、单元测试。不通过禁止合并，main 永远可部署。

### 15. 分层缓存策略

- CDN：静态资源、ISR 页面、i18n 包
- Redis：高频列表、公告、博客、标签
- 写操作主动清缓存，杜绝脏数据
